# GitStream догоняет лидеров через undo, rebase и конфликты

## Краткое резюме

**По базовым операциям GitStream уже на уровне лидеров.** Это частичный stage строк и хунков, stash, ветки, теги, remotes, reset/revert/cherry-pick, blame, история файла и side-by-side diff с word-level подсветкой. Отстаёт он в трёх зонах, которые в 2026 году отличают «силовые» клиенты от простых. **Первая — правка истории**: нет interactive rebase UI, fixup, drop и перемещения коммитов. **Вторая — страховочная сеть**: нет undo, журнала операций и reflog. **Третья — конфликты**: есть только ours/theirs, встроенного 3-way resolver нет. Самый массовый тренд 2025–2026 годов — **worktrees**: их добавили GitHub Desktop, GitKraken, Fork, Sublime Merge и SmartGit. AI-сообщения коммитов стали стандартом у GitHub Desktop, GitKraken, Fork, SmartGit, SourceGit и GitButler. У GitStream нет ни того, ни другого. Зато у него есть то, чего нет у большинства конкурентов: **Sync Assistant**, который диагностирует отклонённый push и делает force-with-lease с backup-ref; askpass-мост поверх системного git; лог команд; работа на Linux бесплатно. Бесплатных кроссплатформенных клиентов уровня SmartGit почти нет. GitHub Desktop, Fork и Sourcetree не работают на Linux, GitKraken Free ограничен публичными репозиториями, а SmartGit бесплатен только для некоммерческого использования. В этой нише прямые соперники GitStream — **SourceGit** (MIT, очень широкий набор функций) и **GitWand** (идентичный стек Tauri 2 + Vue 3 + system git). Рекомендуемый порядок работ такой. **P0**: закрыть UX-долг (четыре системы диалогов, мёртвые кнопки, `window.confirm`, перехват diff-панели ошибками) и построить журнал операций с Undo плюс reflog. **P1**: однокнопочная правка истории, interactive rebase, 3-way resolver, worktrees, command palette и подсветка синтаксиса. **P2**: submodules, LFS, подпись, bisect, AI и PR-интеграция.

## Из двух десятков бесплатных клиентов кроссплатформенных и полнофункциональных единицы

Рынок делится на четыре группы. Первая — «мейнстрим»: GitHub Desktop, Sourcetree, GitKraken, Fork, Sublime Merge, SmartGit. Вторая — классические open-source клиенты: Git Extensions, Git Cola, gitg, Gittyup. Третья — новая волна на Tauri, Electron и GPUI: GitButler, GitWand, AngKorGit, rgitui, GitDesktop. Четвёртая — терминальные клиенты: lazygit, gitui, tig. Важное наблюдение: **«бесплатно» почти всегда означает компромисс**. GitKraken Community работает только с локальными репозиториями и публичными remote; приватные репозитории и интеграции требуют Pro ([GitKraken pricing](https://www.gitkraken.com/pricing)). SmartGit бесплатен лишь для OSS-разработчиков, образования, НКО и хобби, заявки проверяются вручную ([SmartGit non-commercial](https://www.smartgit.dev/register-non-commercial/)). Fork стоит **$59.99** при бесплатной оценке ([fork.dev](https://fork.dev)). Sublime Merge стоит **$99**, оценка у него бессрочная, но лицензия «required for continued use» ([Sublime HQ store](https://www.sublimehq.com/store)). GitButler распространяется под **FSL-1.1-MIT**, то есть это fair-source, а не OSI open source ([LICENSE](https://github.com/gitbutlerapp/gitbutler/blob/master/LICENSE.md)).

Из этой картины следует стратегический вывод. Свободной нишей остаётся **бесплатный кроссплатформенный клиент с функциональностью уровня SmartGit, включая Linux**. Её отмечают и сами заметки исследования: у GitHub Desktop и Sourcetree нет Linux-сборок, GitKraken Free урезан, SmartGit требует подтверждения права на бесплатную лицензию. GitStream уже стоит в этой нише. Конкурентов за неё двое. **SourceGit** покрывает interactive rebase, worktrees, submodules, LFS, bisect, патчи, создание PR и AI-сообщения на 14 языках, включая русский ([README](https://github.com/sourcegit-scm/sourcegit)). **GitWand** — «стековый близнец» GitStream с merge preview, авторазрешением тривиальных конфликтов, PR-интеграцией и панелью агентов ([README](https://github.com/devlint/GitWand)). Именно с ними, а не с GitKraken, GitStream сравнят первые пользователи.

## Безопасный push, askpass и лог команд редки даже у платных клиентов

**Sync Assistant — самая оригинальная функция GitStream.** Он распознаёт отклонённый non-fast-forward push и отличает «переписанный коммит» (то же дерево, другой SHA) от настоящего расхождения. Для первого случая он предлагает `--force-with-lease` с backup-ref `refs/gitstream/backup/<branch>`, для второго — pull --rebase или merge. Ни у одного из восьми сравниваемых клиентов такой диагностики в источниках не найдено. Ближе всего по духу GitButler Timeline со снапшотами перед крупными действиями ([docs](https://docs.gitbutler.com/features/timeline)) и молодой GitCat с «Safety Manager», который делает снапшот перед каждой мутацией ([GitCat](https://github.com/zangjiucheng/GitCat)). Принцип «никаких тихих деструктивных действий» совпадает с главным трендом 2026 года: даже AI-разрешение конфликтов в GitHub Desktop подаётся как предложение, которое можно «review, accept, or edit» ([GitHub Changelog](https://github.blog/changelog/2026-06-26-github-desktop-3-6-worktrees-and-deeper-copilot-integration/)).

**Ставка на системный git CLI вместе с askpass-мостом даёт совместимость.** Клиентам на libgit2 и JGit её приходится достраивать. Gitnuro поддержку git-credential-manager получил только в бете 2.0 ([releases](https://github.com/JetpackDuba/Gitnuro/releases)), AngKorGit и Gittyup работают через libgit2 ([AngKorGit](https://github.com/cheat2001/angkorgit), [Gittyup](https://github.com/Murmele/Gittyup)). У GitStream hooks, credential helpers и пользовательский конфиг работают «как в терминале», а сетевой таймаут ставится на паузу, пока открыт диалог ввода. Минус такой архитектуры — накладные расходы на spawn процессов. На практике его компенсирует потоковое чтение и виртуализация, которые в GitStream уже есть.

**Окно Git output — функция, которую пользователи любят больше всего.** Это не наша интерпретация: автор lazygit пишет, что видимый по умолчанию лог команд — «one of the things people like best about Lazygit», потому что он снимает ощущение, что «UI делает что-то неожиданное» ([Lazygit 5 Years On](https://jesseduffield.com/Lazygit-5-Years-On/)). Sublime Merge строит маркетинг на фразе «When you're using Sublime Merge, you're using Git» ([sublimemerge.com](https://www.sublimemerge.com/)). Из бесплатных GUI похожий лог есть у SourceGit.

Остальные сильные стороны — дерево репозиториев с группами и drag-and-drop, статистика с heatmap и **русская локализация** — встречаются у конкурентов, но редко все вместе. Среди изученных клиентов русский язык подтверждён только у SourceGit и Gittyup ([SourceGit](https://github.com/sourcegit-scm/sourcegit), [Gittyup](https://murmele.github.io/Gittyup/)). Tauri вместо Electron — тоже аргумент. Чаще всего пользователи жалуются на медлительность и память: GitKraken на больших репозиториях, Sourcetree с «interface hanging during refreshes» ([G2](https://www.g2.com/products/axosoft-gitkraken-desktop/reviews?page=3), [Atlassian](https://jira.atlassian.com/browse/SRCTREEWIN-3267)). Оговорка: на Linux у Tauri есть общий риск WebKitGTK. GitWand, например, в dev-режиме требует `WEBKIT_DISABLE_COMPOSITING_MODE=1` ([README](https://github.com/devlint/GitWand)).

## Восемь зон, где GitStream отстаёт от базовой линии 2026 года

**Правка истории — самый заметный пробел.** Interactive rebase UI есть у Git Extensions, Git Cola, Gitnuro, SourceGit, AngKorGit, rgitui, Fork, GitKraken и Sourcetree ([сводка open-source](https://github.com/sourcegit-scm/sourcegit), [Fork](https://fork.dev), [GitKraken](https://help.gitkraken.com/gitkraken-client/interactive-rebase)). Важнее другое: лидеры делают правку истории **одним действием без явного запуска rebase**. В lazygit на любом коммите доступны `s` squash, `f` fixup, `d` drop, `ctrl+j/k` для перемещения, а `A` вливает staged-изменения в старый коммит. Для последнего в документации сказано: «runs an interactive rebase in the background» ([lazygit README](https://github.com/jesseduffield/lazygit)). В Magit instant fixup — это `git commit --fixup` и сразу `git rebase --autosquash` ([Magit manual](https://docs.magit.vc/magit/Editing-any-reachable-commit-and-rebasing-immediately.html)). JetBrains даёт Fixup, Squash Into, Drop и «Extract Selected Changes to Separate Commit» прямо из лога ([JetBrains](https://www.jetbrains.com/help/idea/edit-project-history.html)). Механизм сценарного `GIT_SEQUENCE_EDITOR` в GitStream уже есть для reword, так что стоимость этих операций невелика.

**Страховочной сети нет.** GitKraken 11.8 распространил Undo/Redo на interactive rebase, cherry-pick и AI-коммиты ([блог GitKraken](https://www.gitkraken.com/blog/gitkraken-desktop-11-8-visibility-where-it-matters-undo-when-it-doesnt)). В lazygit undo построен на reflog ([README](https://github.com/jesseduffield/lazygit)). В jj есть operation log с полным снимком refs и working copy и `jj op restore` ([jj docs](https://docs.jj-vcs.dev/latest/operation-log/)). Fork продаёт «Reflog to restore lost commits» ([fork.dev](https://fork.dev)). В GitStream зачаток этого — только backup-ref при force push.

**Конфликты решаются лишь на уровне целого файла.** Эталон — JetBrains: три панели (Local | Result | Theirs), «Apply non-conflicting changes», «Resolve simple conflicts», действия Accept и Ignore на каждом чанке ([JetBrains](https://www.jetbrains.com/help/idea/resolve-conflicts.html)). Среди новых open-source клиентов трёхпанельный resolver есть у AngKorGit и rgitui. GitWand дополнительно автоматически разрешает тривиальные конфликты и показывает merge preview до слияния ([AngKorGit](https://github.com/cheat2001/angkorgit), [rgitui](https://github.com/noahbclarkson/rgitui), [GitWand](https://github.com/devlint/GitWand)). Даже у GitKraken resolver в Free недоступен. Значит, бесплатный 3-way resolver — реальное конкурентное преимущество, а не просто паритет.

**Worktrees стали стандартом за один год** благодаря параллельным AI-агентам. Их добавили GitHub Desktop 3.6 (меню «Current Worktree» рядом с Repository и Branch), GitKraken 12.0 (Agent Sessions View), Fork 2.59–2.68, Sublime Merge 2130 и SmartGit 26.1 ([GitHub Changelog](https://github.blog/changelog/2026-06-26-github-desktop-3-6-worktrees-and-deeper-copilot-integration/), [ComponentSource](https://www.componentsource.com/product/gitkraken/releases/2959401), [SmartGit 26.1](https://www.smartgit.dev/whats-new/26_1/)).

**Обнаруживаемость функций уступает конкурентам.** Command palette есть у GitKraken (Ctrl+P), Fork (Quick Launch с fuzzy-поиском путей), Sublime Merge и почти у всех новых Tauri-клиентов: AngKorGit, Graft, rgitui ([GitKraken](https://help.gitkraken.com/start-here/interface), [Fork](https://releasebot.io/updates/git-fork), [Graft](https://github.com/Dancode-188/graft)). Drag-and-drop ветки на ветку с меню merge/rebase есть у GitKraken и Tower ([GitKraken](https://help.gitkraken.com/?p=1957), [Tower](https://www.git-tower.com/docs/ai/git-features/)). Коммит в GitStream спрятан в модальный диалог, а GitHub Desktop держит поля Summary/Description и кнопку «Commit to BRANCH» внизу списка изменений ([GitHub Docs](https://docs.github.com/en/enterprise-server@3.9/desktop/making-changes-in-a-branch/committing-and-reviewing-changes-to-your-project-in-github-desktop)).

**Diff и поиск беднее, чем у лидеров.** Подсветки синтаксиса нет, хотя у Sublime Merge она охватывает 40+ языков. Фильтр лога клиентский и работает только по загруженным коммитам. Sublime Merge ищет по сообщению, автору, пути и **содержимому** по мере ввода, с операторами `and/or/not/before:/after:` ([changelog](https://www.sublimemerge.com/download)). JetBrains фильтрует лог по пути, автору, дате и ветке ([JetBrains](https://www.jetbrains.com/help/idea/2025.2/investigate-changes.html)).

**Слой «экосистемы» отсутствует целиком**: submodules, LFS, подпись коммитов, bisect, патчи, custom actions. У SourceGit и Git Extensions всё это есть ([SourceGit](https://github.com/sourcegit-scm/sourcegit), [Git Extensions docs](https://git-extensions-documentation.readthedocs.io/en/main/)). Gitnuro 2.0 добавил SSH-подпись, gitg 50 добавил custom actions ([Gitnuro](https://github.com/JetpackDuba/Gitnuro/releases), [gitg NEWS](https://gitlab.gnome.org/GNOME/gitg/-/blob/master/NEWS)).

**AI и PR-интеграции тоже нет.** В 2026 году AI-сообщения коммитов — обязательная галочка, но тренд смещается к **opt-in через уже установленный CLI агента**. Fork делегирует генерацию Claude, Codex и Cursor ([releasebot](https://releasebot.io/updates/git-fork)), AngKorGit использует залогиненный AI CLI, GitDesktop выключает весь AI одним переключателем и ходит в GitHub через `gh` ([AngKorGit](https://github.com/cheat2001/angkorgit), [GitDesktop](https://github.com/theBGuy/GitDesktop)). SmartGit 25.1 явно спрашивает согласие перед отправкой данных ([SmartGit 25.1](https://www.smartgit.dev/whats-new/25_1/)).

## Roadmap: сначала UX-долг и страховочная сеть, затем история и конфликты

Шкала сложности: **S** — до нескольких дней, **M** — одна-две недели, **L** — несколько недель и больше. Логика приоритетов такая. В P0 входят дешёвые исправления, которые убирают ощущение «сырости», и журнал операций. Журнал операций стоит первым из функций потому, что после него правку истории в P1 можно выпускать без страха: любую ошибку пользователь откатит одной кнопкой.

## Одна дизайн-система вместо четырёх

Исследование не нашло качественных источников 2024–2026 годов, где пользователи прямо называют «слишком много модальных окон» или «нет тостов» главной претензией. Поэтому рекомендации ниже опираются на документированные паттерны лидеров, а не на опросы. Задокументированная жалоба на клиенты конкурентов другая: **визуальный шум**, «5000 UI elements and text everywhere» в Sourcetree, GitKraken, VS Code и GitHub Desktop ([HN](https://news.ycombinator.com/item?id=33740619)). У GitStream пять-шесть постоянных панелей, поэтому сдержанные умолчания и прогрессивное раскрытие для него важнее новых кнопок. Ориентир по стилю — обновления Linear: приглушённый сайдбар, более мягкие разделители, тёплые нейтральные серые и плотность «without it feeling overwhelming» ([Linear](https://linear.app/now/behind-the-latest-design-refresh)). ## Заключение

У GitStream нет недостатка функций, зато есть асимметрия. В синхронизации с remote он осторожнее и умнее большинства конкурентов, а в локальной правке истории беззащитнее. Отсюда главный вывод: **журнал операций с Undo нужно ставить не в один ряд с остальными фичами, а раньше них**. Он превращает уже существующий принцип Sync Assistant («никаких тихих деструктивных действий») в общее свойство приложения. Кроме того, он снижает риск всего P1: fixup, drop, interactive rebase и drag-and-drop веток становятся безопасными экспериментами, а не поводом для подтверждающих диалогов. Второй рычаг — единый реестр команд. Одна архитектурная правка закрывает сразу три пункта аудита: вечно неактивные Merge/Rebase, меню графа из десяти серых пунктов и отсутствие палитры.

Стратегически на GitStream давят не GitKraken и Fork, а бесплатные SourceGit и GitWand. Их широту быстро не догнать, поэтому выигрывать стоит глубиной в рискованных сценариях. Бесплатный трёхпанельный resolver, которого в GitKraken Free нет, merge preview через `git merge-tree` и Undo для любой операции на Linux вместе образуют позиционирование, которое не занял ни один из изученных клиентов. AI и PR-интеграцию разумно отложить и делать в модели Fork и GitDesktop, через уже установленные `claude`, `codex`, `gh` и `glab` с одним выключателем. Так GitStream получит актуальные функции без собственного облачного бэкенда и без компромиссов в приватности.
