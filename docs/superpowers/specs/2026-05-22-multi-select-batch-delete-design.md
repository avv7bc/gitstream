# Множественный выбор и пакетное удаление в BranchPanel

**Дата:** 2026-05-22
**Статус:** утверждён

## Цель

Дать возможность выбирать несколько элементов в панели веток/тегов
(`BranchPanel.vue`) с помощью shift- и ctrl/cmd-клика и удалять выбранные теги
или локальные ветки одной операцией.

## Контекст

Сейчас `BranchPanel.vue` хранит одиночный `selectedKey: ref<string | null>` —
клик подсвечивает ровно один элемент. Удаление тега (`handleDeleteTagCtx`) и
локальной ветки (`handleDeleteCtx`) работает только с одним правым кликом
(`ctxTag` / `ctxBranch`). Бэкенд-команды `do_delete_tag` и `do_delete_branch`
принимают один элемент за вызов.

## Модель выбора

Одиночный `selectedKey` заменяется на:

- `selectedKeys: ref<Set<string>>` — набор выбранных ключей
- `anchorKey: ref<string | null>` — якорь для shift-диапазона

Ключи сохраняют существующий формат с префиксом раздела: `local:<name>`,
`remote:<name>`, `tag:<name>`, `stash:<index>`.

`selectItem(key, event)` реагирует на модификаторы:

- **Обычный клик** (без модификаторов) — `selectedKeys = {key}`, `anchorKey = key`
- **Ctrl/Cmd+клик** — переключить `key` в наборе; `anchorKey = key`
- **Shift+клик** — диапазон от `anchorKey` до `key` по отфильтрованному списку
  **того же раздела**; `selectedKeys` заменяется содержимым диапазона,
  `anchorKey` не меняется. Если `anchorKey` пуст или находится в другом
  разделе — поведение как у обычного клика.

Диапазон не пересекает границы разделов: нельзя одним shift-кликом выделить
часть веток и часть тегов. Раздел элемента определяется по префиксу ключа;
упорядоченный список ключей раздела берётся из соответствующего computed
(`localBranches`, `remoteBranches`, `filteredTags`, `filteredStashes`).

Подсветка в шаблоне: `:class="{ selected: selectedKeys.has(key) }"`.

Множественный выбор как взаимодействие доступен во всех четырёх разделах
единообразно. Пакетные операции — только для тегов и локальных веток (см. ниже).

При смене репозитория списки `tags`/`branches` перезагружаются; устаревшие
ключи в `selectedKeys` просто перестают совпадать с элементами. Дополнительно
наборы выбранных элементов для операций вычисляются пересечением с текущими
видимыми списками, поэтому скрытые фильтром или отсутствующие элементы в
удаление не попадают.

## Контекстное меню

При правом клике по элементу:

- если элемент **не входит** в `selectedKeys` — выбор сбрасывается на него
  одного (`selectedKeys = {key}`, `anchorKey = key`), затем показывается меню;
- если элемент **входит** в `selectedKeys` — выбор сохраняется как есть.

### Меню тегов

- «Delete Tag» → «Delete N Tags», когда выбрано 2+ тегов
- «Push Tag» → «Push N Tags», когда выбрано 2+ тегов
- обе операции выполняются циклом по выбранным тегам

### Меню локальных веток

- «Delete» → «Delete N Branches», когда выбрано 2+ локальных веток
- одноцелевые пункты (Checkout, Merge, Rebase, Create branch from here,
  Rename, Push) **отключаются** (`disabled`), когда выбрано 2+ веток
- текущая ветка (`is_current`) исключается из списка на удаление; если после
  исключения удалять нечего — пункт «Delete» отключён

### Удалённые ветки

Множественный выбор только подсвечивает элементы. Пакетного удаления нет —
удаление remote-веток сейчас не реализовано и в объём задачи не входит.

## Пакетное удаление

### Теги

`handleDeleteTagCtx` собирает выбранные теги (пересечение `selectedKeys` с
`filteredTags`) в `targetTags` и открывает диалог подтверждения.

Диалог: `ConfirmDialog` со списком имён тегов (`items`), сообщением
(«Delete tag 'x'?» для одного, «Delete N tags?» для нескольких) и чекбоксом
«Also delete on remote '<remote>'» (когда есть remote).

`confirmDeleteTag(alsoRemote)` циклом вызывает `deleteTag(name)`, при чекбоксе —
`pushTag(remote, name, true)`. Ошибки накапливаются и показываются одним
`window.alert`. После удаления — `emit("tagsChanged")`, очистка выбора.

### Локальные ветки

`handleDeleteCtx` собирает выбранные локальные ветки (исключая текущую) в
`targetBranches`, открывает диалог со списком имён.

`confirmDelete` циклом вызывает `deleteBranch(name, false)`. Ветки с ошибкой,
содержащей «not fully merged», собираются в отдельный список; остальные ошибки
накапливаются для `alert`. Если список «не смерженных» не пуст — открывается
второй диалог force-delete со списком именно этих веток; `confirmForceDelete`
циклом вызывает `deleteBranch(name, true)`.

После удаления — `emit("branchesChanged")`, очистка выбора.

## Изменение ConfirmDialog

В `ConfirmDialog.vue` добавляется необязательный проп `items?: string[]`.
Когда он передан и непуст, под сообщением рендерится прокручиваемый список
`<ul class="confirm-list">` с ограничением высоты и `overflow: auto`.
Существующие вызовы без `items` не меняются.

## Затрагиваемые файлы

- `src/components/BranchPanel.vue` — модель выбора, контекстные меню,
  пакетные обработчики удаления
- `src/components/dialogs/ConfirmDialog.vue` — проп `items` и рендер списка
- `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json` —
  патч-инкремент версии

Бэкенд не меняется: `do_delete_tag` и `do_delete_branch` вызываются циклом
с фронтенда.

## Вне объёма

- Удаление remote-веток
- Пакетные операции для stash
- Изменение бэкенд-команд под пакетный приём списков
